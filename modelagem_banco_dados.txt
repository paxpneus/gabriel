MODELAGEM DO BANCO DE DADOS - PAX PNEUS BACKEND
Gerado a partir dos models Sequelize e de src/config/sequelize-associations.ts.

Observacao importante:
- Este documento descreve a modelagem declarada no codigo da aplicacao.
- Para confirmar 100% o estado real do banco em producao/desenvolvimento, seria ideal comparar com information_schema ou pg_dump --schema-only.
- Nao foi necessario rodar SQL para montar esta primeira versao.

Padroes gerais:
- Banco: PostgreSQL.
- ORM: Sequelize.
- A maioria das tabelas usa id UUID como chave primaria.
- A maioria das tabelas usa timestamps com underscored: created_at e updated_at.
- Os documentos como CPF, CNPJ e CEP passam por normalizadores em alguns models antes de salvar.


1. VISAO GERAL DOS MODULOS

O banco esta dividido principalmente nos seguintes dominios:

1. Integracoes
   - integrations
   - config_tokens
   - integration_mappings
   - applications

2. Vendas
   - customers
   - stores
   - orders
   - order_items
   - steps
   - order_histories

3. Warehouse / estrutura operacional
   - unit_businesses
   - transporters
   - carrier_label_ranges
   - carrier_import_layouts
   - printer_configs

4. Usuarios e permissoes
   - roles
   - users
   - user_config
   - user_unit_business

5. Entrada de mercadorias / notas
   - invoices
   - invoice_items
   - entrance_scan_logs
   - unmapped_invoice_products

6. Expedicao
   - expedition_batches
   - expedition_batch_items
   - expedition_batch_invoices
   - expedition_scan_logs

7. Estoque e inventario
   - products
   - suppliers
   - product_supplier_maps
   - stocks
   - inventory_batches
   - inventory_batch_items
   - inventory_batch_logs


2. INTEGRACOES

Tabela: integrations
Finalidade: representa sistemas/canais externos integrados, como marketplace, ERP, canal de venda ou sistema interno.

Campos principais:
- id: UUID, PK.
- name: string(255), obrigatorio.
- type: enum CHANNEL | SYSTEM, obrigatorio.
- lock_today_orders: boolean, default false.
- api_url: string(255), obrigatorio, validado como URL.
- document: string(11), opcional.
- cnaes: array de string, opcional.
- allowed_channels: array de string, opcional.
- created_at, updated_at.

Relacionamentos:
- 1 integration tem 1 config_token.
- 1 integration tem N orders.
- 1 integration tem N invoices.
- 1 integration tem N expedition_batches.
- 1 integration tem N integration_mappings.
- 1 integration pode estar associada a N unit_businesses.


Tabela: config_tokens
Finalidade: armazena credenciais e tokens OAuth/API de uma integracao.

Campos:
- id: UUID, PK.
- integrations_id: UUID, FK para integrations.id, obrigatorio.
- access_token: text, opcional.
- refresh_token: text, opcional.
- client_id: string(255), obrigatorio.
- client_secret: string(255), obrigatorio.
- access_token_url: string(255), opcional.
- auth_url: string(255), opcional.
- oauth_state: string(255), opcional.
- callback_url: string(255), opcional.
- created_at, updated_at.

Relacionamentos:
- N:1 com integrations.
- Pelo codigo, integrations tem 1 config_tokens.


Tabela: integration_mappings
Finalidade: relaciona ids internos da aplicacao com ids externos de uma integracao.

Campos:
- id: UUID, PK.
- entity_type: enum PRODUCT | INVOICE, obrigatorio.
- internal_id: string(100), obrigatorio.
- integrations_id: UUID, FK para integrations.id.
- external_id: string(100), obrigatorio.
- unit_business_id: UUID, FK para unit_businesses.id, obrigatorio.
- created_at, updated_at.

Relacionamentos:
- N:1 com integrations.
- N:1 com unit_businesses.


Tabela: applications
Finalidade: representa aplicativos externos autorizados a consumir a API da PAX Pneus via api_key/api_secret e token Bearer temporario.

Campos:
- id: UUID, PK.
- name: string(120), obrigatorio.
- description: text, opcional.
- role_id: UUID, FK para roles.id, obrigatorio.
- api_key: string(80), obrigatorio, unico.
- api_secret_hash: string(255), obrigatorio. O segredo original e exibido apenas na criacao/rotacao.
- allowed_routes: array de string, obrigatorio, default [].
- rate_limit_max_requests: integer, default 120.
- rate_limit_window_seconds: integer, default 60.
- token_version: integer, default 0. Incrementado para revogar tokens emitidos.
- last_login_at: date, opcional.
- revoked_at: date, opcional.
- is_active: boolean, default true.
- created_at, updated_at.

Relacionamentos:
- N:1 com roles.


3. VENDAS

Tabela: customers
Finalidade: cadastro de clientes dos pedidos.

Campos:
- id: UUID, PK.
- name: string(255), obrigatorio.
- type: enum F | J, obrigatorio. F = pessoa fisica, J = pessoa juridica.
- document: string(14), obrigatorio, unico.
- created_at, updated_at.

Relacionamentos:
- 1 customer tem N orders.


Tabela: stores
Finalidade: lojas ou pontos/canais de venda associados a pedidos e notas.

Campos:
- id: UUID, PK.
- name: string(255), opcional.
- id_store_system: string(255), opcional.
- created_at, updated_at.

Relacionamentos:
- 1 store tem N orders.
- 1 store tem N invoices.

Observacao:
- No model Invoice, store_id esta marcado como unique: true, o que na pratica tende a transformar o relacionamento store -> invoices em 1:1 no banco, apesar da associacao declarar hasMany.


Tabela: orders
Finalidade: pedidos de venda vindos de integracoes/canais.

Campos:
- id: UUID, PK.
- integrations_id: UUID, FK para integrations.id, obrigatorio.
- customer_id: UUID, FK para customers.id, obrigatorio.
- store_id: UUID, FK para stores.id, opcional.
- id_order_system: string(100), opcional.
- number_order_system: string(100), opcional.
- number_order_channel: string(100), obrigatorio.
- actual_step: string(50), default PENDING.
- actual_situation: string(50), default ACTIVE.
- collection_date: date, opcional.
- date: date, opcional.
- totalPrice: decimal, opcional.
- nfe_emitted: boolean, default false.
- waiting_acceptance: boolean, default false.
- internal_status: enum OPEN | WAITING CHANNEL VALIDATION | WAITING FOR NFE EMISSION | CANCELLED | EMITTED | UNKNOWN, default OPEN.
- created_at, updated_at.

Relacionamentos:
- N:1 com integrations.
- N:1 com customers.
- N:1 com stores.
- 1 order tem N order_items.
- 1 order tem N order_histories.
- N:N com steps atraves de order_histories.


Tabela: order_items
Finalidade: itens/produtos vendidos dentro de um pedido.

Campos:
- id: UUID, PK.
- order_id: UUID, FK para orders.id, obrigatorio.
- name: string(255), obrigatorio.
- sku: string(100), obrigatorio.
- unit: string(20), opcional.
- quantity: integer, default 1.
- price: decimal(10,2), obrigatorio.
- created_at, updated_at.

Relacionamentos:
- N:1 com orders.
- onDelete CASCADE para order_id.


Tabela: steps
Finalidade: etapas de fluxo/processamento dos pedidos.

Campos:
- id: UUID, PK.
- label_admin: string(100), obrigatorio.
- label_system: string(100), obrigatorio.
- sequence: integer, default 0.
- created_at, updated_at.

Relacionamentos:
- 1 step tem N order_histories.
- N:N com orders atraves de order_histories.


Tabela: order_histories
Finalidade: historico de mudancas/processamentos de um pedido por etapa.

Campos:
- id: UUID, PK.
- order_id: UUID, FK para orders.id, obrigatorio.
- step_id: UUID, FK para steps.id, obrigatorio.
- situation: string(100), obrigatorio.
- date: date, default NOW.
- json_data: JSON, opcional.
- result: enum success | errors | processing, default processing.
- created_at, updated_at.

Relacionamentos:
- N:1 com orders.
- N:1 com steps.
- Funciona como tabela pivot entre orders e steps.

Relacionamentos:

- 1 unit_business tem N stocks.

Tabela: transporters
Finalidade: transportadoras.

Campos:
- id: UUID, PK.
- id_system: string(100), opcional.
- name: string(255), obrigatorio.

Relacionamentos:

- 1 transporter tem 1 carrier_import_layout no codigo.

Finalidade: faixas de CEP/rotas de transportadora para geracao ou interpretacao de etiquetas.

Campos:
- id: UUID, PK.

- cep_start: string(15), obrigatorio.

Relacionamentos:

Finalidade: configuracao de layout de importacao de tabelas de transportadora.

Campos:
- id: UUID, PK.
- transporter_id: UUID, FK para transporters.id, obrigatorio, unique.
- name: string(255), obrigatorio.
- type: enum EXCEL | CSV, default EXCEL.
- sheet_name: string(255), opcional.
- data_start_row: integer, default 2.
- mapping_mode: enum HEADER | COLUMN, default HEADER.
- zip_from_label: string(255), obrigatorio.
- zip_to_label: string(255), obrigatorio.
- route_code_label: string(255), opcional.
- route_acronym: string(100), opcional.
- destination_label: string(255), opcional.
- observation_label: string(255), opcional.
- metadata: JSONB, opcional.
- active: boolean, default true.
- created_at, updated_at.

Relacionamentos:
- 1:1 com transporters pelo codigo.


Tabela: printer_configs
Finalidade: configuracoes de impressora por unidade de negocio.

Campos:
- id: UUID, PK.
- unit_business_id: UUID, FK para unit_businesses.id, obrigatorio.
- server_ip: string(45), obrigatorio.
- printer_name: string(255), obrigatorio.
- is_active: boolean, default true.
- created_at, updated_at.

Relacionamentos:

Campos:

Finalidade: usuarios do sistema.

- cpf: string(14), obrigatorio, unico.
- unit_business_id: UUID, FK para unit_businesses.id, obrigatorio.
- role_id: UUID, FK para roles.id, obrigatorio.

- created_at, updated_at.

Relacionamentos:
- N:1 com unit_businesses.
- N:1 com roles.
- 1 user tem 1 user_config.
- 1 user tem N entrance_scan_logs.

Tabela: user_config
Finalidade: preferencias do usuario.

Campos:
- id: UUID, PK.
- user_id: UUID, FK para users.id, obrigatorio, unico.

- compact_mode: boolean, default false.
- created_at, updated_at.

Relacionamentos:

Finalidade: tabela pivot para liberar acesso de um usuario a varias unidades de negocio.

Campos:

- created_at, updated_at.

Constraints:
- Indice unico composto em user_id + unit_business_id.

Relacionamentos:
- N:1 com users.
- N:1 com unit_businesses.
- Implementa N:N entre users e unit_businesses.

Tabela: invoice_items
Finalidade: itens esperados/recebidos de uma nota.

- quantity_expected: integer, default 0.
- quantity_received: integer, default 0.
- status: enum PENDING | FINISHED, default PENDING.
- created_at, updated_at.

- beforeUpdate marca status como FINISHED quando quantity_received == quantity_expected.

Relacionamentos:
- N:1 com invoices.
- N:1 com products.
- 1 invoice_item tem N entrance_scan_logs.

Constraints em migrations:
- Existe constraint unica para invoice_id + product_id em invoice_items.

Tabela: stocks
Finalidade: saldo de estoque por produto e unidade de negocio.

Campos:
- id: UUID, PK.
- product_id: UUID, FK para products.id, obrigatorio, unique no model.

- created_at, updated_at.

Observacao importante:
- No model, product_id e unit_business_id aparecem individualmente com unique: true. Isso pode impedir mais de um estoque por produto e mais de um estoque por unidade isoladamente.
- Em modelagem normal de estoque por unidade, geralmente se espera unicidade composta product_id + unit_business_id. Vale conferir o estado real no banco se isso estiver causando comportamento estranho.


Tabela: inventory_batches

10. PONTOS DE ATENCAO NA MODELAGEM

1. Associacoes fora da funcao setupAssociations
No arquivo src/config/sequelize-associations.ts, parte dos relacionamentos de stocks/inventory/unmappedProducts aparece depois do fechamento da funcao setupAssociations().
Se esse arquivo for importado, essas associacoes podem ser executadas no load do modulo, mas nao seguem o mesmo padrao da funcao. Vale revisar para evitar comportamento inesperado.

2. Unique individual em stocks
O model Stock marca product_id e unit_business_id como unique individualmente.
Se a intencao for estoque por produto por unidade, o mais comum seria uma constraint composta:
UNIQUE(product_id, unit_business_id)

3. Store em invoices
Invoice.store_id esta como unique: true, mas a associacao Store.hasMany(Invoice) sugere varias invoices por store.
Vale decidir se e 1:1 ou 1:N.

4. CarrierLabelRange por transporter
carrier_label_ranges.transporter_id esta unique: true, mas a associacao Transporter.hasMany(CarrierLabelRange) sugere varias faixas por transportadora.
Para faixas de CEP, normalmente faz sentido N faixas por transportadora.

5. Supplier sem FK direta no mapping
product_supplier_maps usa supplier_cnpj, nao supplier_id.
Isso permite mapear fornecedor por documento, mas perde integridade referencial direta com suppliers.id.

6. InventoryBatch BatchIdForDivergency
O atributo no model esta em camel/pascal case, mas a associacao usa batch_id_for_divergency.
Como underscored esta ativo, pode funcionar, mas e um ponto que merece padronizacao.

Se quiser validar esta documentacao contra o banco real, rode estes SQLs e me envie o resultado:

1) Listar tabelas:
SELECT table_name
FROM information_schema.tables
WHERE table_schema = 'public'

2) Listar colunas, tipos e nullability:
SELECT
  table_name,
  column_name,
  data_type,
  udt_name,
  is_nullable,
  column_default
FROM information_schema.columns
WHERE table_schema = 'public'
ORDER BY table_name, ordinal_position;

3) Listar constraints:
SELECT
  tc.table_name,
  tc.constraint_name,
  tc.constraint_type,
  kcu.column_name,
  ccu.table_name AS foreign_table_name,
  ccu.column_name AS foreign_column_name
FROM information_schema.table_constraints tc
LEFT JOIN information_schema.key_column_usage kcu
  ON tc.constraint_name = kcu.constraint_name
  AND tc.table_schema = kcu.table_schema
LEFT JOIN information_schema.constraint_column_usage ccu
  ON ccu.constraint_name = tc.constraint_name
  AND ccu.table_schema = tc.table_schema
WHERE tc.table_schema = 'public'
ORDER BY tc.table_name, tc.constraint_type, tc.constraint_name;

4) Listar indices:
SELECT
  tablename,
  indexname,
  indexdef
FROM pg_indexes
WHERE schemaname = 'public'
ORDER BY tablename, indexname;
