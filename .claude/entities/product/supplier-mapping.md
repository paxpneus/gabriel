# SupplierMapping (`src/modules/inventory/supplier-mapping/`)

- Table `product_supplier_maps`: `product_id`, `supplier_cnpj`, `supplier_product_code`, `integrations_id`, `is_physical_override` (`m326`, default false — "EAN físico confirmado", see `physical-ean-owner.md`; sync never creates it).
- Unique index `product_supplier_maps_integrations_id_code_unique (integrations_id, supplier_product_code)` since `m263` — replaced an older `(product_id, supplier_product_code)` unique that blocked the same code mapping to different products across different integrations (legitimate case).
- Trigger `trigger_prevent_supplier_mapping_gtin_conflict` (`m263`, narrowed `m265`): `supplier_product_code` can't equal another product's `ProductConfig.gtin` within the same integration (joins `unit_businesses.integrations_id`). No longer checks `gtin_package`.
- `supplierMappingService.findByProductCode(code, unitBusinessId)` — resolves `integrations_id` for the unit business then looks up the mapping. Reuse this instead of duplicating the `findOne`.
- `supplierMappingService.createFromUnmapped({ productId, unmappedInvoiceProductId, supplierCnpj?, userId? })` — `POST /supplier-mapping/from-unmapped`: links an `UnmappedInvoiceProduct` to an **already-existing** `Product`, without going through `InvoiceItems`. Controller checks `unmapped.integrations_id` against the caller's resolved integration first (404). Returns `CreateFromUnmappedResult` `{ supplierMapping | null, integrationMapping {id, external_id, is_primary} | null, integration {id, name}, integrationMappings[] }` — the last one is `integrationMappingService.findProductMappingsInIntegration` (all of the product's mappings in that integration, `erp_data` reduced to `{name, ean}`); front warns when `length > 1`.
  - Branch on whether the product already has an `integration_mapping` in the unmapped's integration (`findExternalIdsMap`):
  - **Already mapped** (old flow): code = `unmapped.ean ?? unmapped.sku`, `assertEanFreeForProduct`, then SupplierMapping **always `is_physical_override: true`** (existing same-product row is marked; other product → error). Any error propagates. If `external_id` is set, `createOrUpdateIntegrationMapping` too (may be born non-primary). Unmapped row deleted in the transaction.
  - **Not mapped** — only `type ERROR_CATALOG` with reason `UNMAPPED_REASON_NEW_CATALOG_PRODUCT` / `UNMAPPED_REASON_INVOICE_PRODUCT_NOT_IN_DB` (constants in `unmapped-invoice-product.types.ts`, also used where the rows are created) **and** `external_id`; otherwise `SupplierMappingError PRODUCT_NOT_MAPPED_IN_INTEGRATION` with a lay message per reason (front only shows `error`). Creates the integration mapping (primary only if the product has none there — never swaps the primary; manual via `PUT /integration-mapping/product/:productId/:id`), audited (INTEGRATION_MAPPING + PRODUCT). SupplierMapping is tried inside a **savepoint** (`sequelize.transaction({ transaction: t })`) — any failure (EAN in use, override, no EAN/SKU) is logged and swallowed, `supplierMapping: null`. `external_id` already pointing at another product → plain error (rollback). After commit, `unmappedInvoiceProductService.resolveFromCreatedProduct` closes every UNMAPPED row of that `external_id` (invoice rows get the `InvoiceItem` + batch/PDV sync) instead of a bare delete.
  - `ERROR_CATALOG_DUPLICATE`: ambiguous code — only the integration mapping (no SupplierMapping, no not-mapped gate), row deleted; requires `external_id`.
- Product-scoped CRUD, always scoped to `product_id` (route) + caller's resolved `integrations_id` (same tenant scope as `index`; body `product_id`/`integrations_id` ignored):
  - `GET /supplier-mapping/product/:productId` → `findByProductId`: paginated via `repository.findPaginated` forced where.
  - `POST /supplier-mapping/product/:productId` → `createForProduct` (body `supplier_product_code`, `supplier_cnpj?`): pre-checks `PRODUCT_NOT_MAPPED_IN_INTEGRATION` / `EAN_HAS_PHYSICAL_OVERRIDE` / `EAN_OWNED_BY_ANOTHER_PRODUCT` (with `owners`), then reuses `create`; closes the EAN's `ERROR_SCAN` rows and audits. FK error → "Produto não encontrado" (can't pre-check via `productService`: circular import, product.service imports supplierMappingService).
  - `POST /supplier-mapping/product/:productId/physical-owner` → `assignPhysicalOwner` — see `physical-ean-owner.md`.
  - `PUT /supplier-mapping/product/:productId/:id` → `updateForProduct`: only sent fields; uses `repository.update` (instance) so `beforeUpdate` CNPJ-cleaning hook runs. 404 if not that product/integration. Override row: only admin/developer; code change is pre-checked. `is_physical_override: false` deactivates the override (audited, see `physical-ean-owner.md`); `true` → error.
  - `DELETE /supplier-mapping/product/:productId/:id` → `deleteForProduct`: single `bulkDelete` with scoped where; 404 if 0 rows. Override row: only admin/developer, audited.
  - Generic routes (`create`/`update`/bulk) drop `is_physical_override` from the body and pre-check the code; bulk filters override rows for non-admins.
  - `/add/item` (`invoice-items`) runs `assertEanFreeForProduct` before creating the mapping; controller returns `code`.
- `GET /supplier-mapping/integration-pending/get` — see `../../modules/integration-pending-report.md`.
